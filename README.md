# 居家监测告警的响应时效与设备可用性分析

以下资料为合成记录，不含实际个人信息。文件以 UTF-8 编码，普通字段含日期或本地时间（东八区），分号表示同一字段的多值。空值表示在该记录中未提供，不自动当零。表内的凭据编号用于核对记录归属。

## 数据来源

- `data/bindings.csv`：同一位置的设备换装；绑定记录采用权威本地时间，结束点不含。
- `data/clock_checks.csv`：将 offset_sec 加到来源时间得到本地中心时刻，margin_sec 是两侧界限；区间针对来源时钟。
- `data/calls.csv`：ref 是源端转接凭证，来源为空的 person 必须从绑定确认。
- `data/receipts.csv`：签收包含原始归属引用和时间来源。
- `data/outage_notices.csv`：故障工作单和发布给运营台的停服范围；仅指定通道受影响。
- `data/manual_review.csv`：人工核对回函；有的证据在月结后才到。
- `data/sla.csv`：时间单位秒，抵扣单位分；应纳入且必须上门的类别由合同载明。
- `data/signed_months.csv`：历史已发月单。`cutoff` 是月单当时收录凭据的截至时间，金额为分。
- `data/signed_obligations.csv`：已发月单按原归属记录的义务明细；`case_credit` 是旧台账已计入事件上限、尚未扣减全站月度上限的金额。旧台账归属或金额不一定正确。

## 环境及检查

使用 Python 3.11.2 标准库，无需网络或额外安装。在项目目录可执行 `python3 -m unittest discover -s tests -v` 核对输入文件、表头、记录形状及业务核对结果。各来源字段及记录数量见 `data-contract.json`。

## 业务核对（careops 包）

承接合同对居家呼叫分别约定接听和上门的时限。`careops` 按校时回执给出的适用时段和误差界限确定来源时间的可能范围，只在住户和响应先后都能确认时作相应认定（计时区间整体越限才认定迟到，整体不越限才认定达时，否则为未决），不取最有利的时间。本工具用于运营时效核对和合同处理，不从读数判断住户的诊疗需要。主要规则：

- 自动归并要求同住户和可核的引用（ref）；人工复核可凭证据拆案或并案；分案后签收只用于它实际回应的一案。
- 停服豁免只影响合同指定的自动通道，电话照常计时；事后补传不能把计划外停服变成豁免；扣除的暂停区间须有对应呼叫与有效停服凭证，重叠只扣一次。
- 一个呼叫有多份有效同类签收时，以能证明的最早一次响应计时；未收到有效签收不等于已知迟到，值班台待办分开列清"尚未联系"与"已联系但缺上门核实"。
- 只将能证明的违约计入应抵扣额，先受同一呼叫上限约束，再受站点月上限约束。旧月单触顶时单个义务改判不直接退款，按全月重算、相对已向承接方确认的累计金额发调整；未决事项不冒充确定差额。

命令（在项目目录执行， `--as-of` 可按凭据截至时点重建历史视角）：

```sh
python3 -m careops todos --station 槐园                    # 值班台待办（复核到达后即时调整）
python3 -m careops summary --station 槐园 --period 2026-03 # 站点-月份汇总：应纳入/达时/迟到/未决、违约率范围、应抵扣额（出单口径，可分通道）
python3 -m careops obligations --station 槐园 --period 2026-03  # 原签月单旧归属义务明细 vs 当前可证明口径
python3 -m careops adjustment --station 槐园 --period 2026-03   # 经上限约束、相对已确认累计金额的调整单（含无经济差额改判与未决事项）
```

后续月份的出单、更正和排班人员查待办都用以上命令在项目内办理，不需要重写历史月单。
